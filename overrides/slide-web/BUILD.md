# BUILD.md — slide-web (HTML / PDF output)

Project-specific commands and structure. Common slide-kit rules: see `AGENTS.md`.

## Stack

- [Slidev](https://sli.dev/) — Vue 3 + Vite ベースのプレゼンフレームワーク
- Themes: 内製2種（internal / external）に共通スタイルを CSS で定義
- PDF export: `playwright-chromium` 経由
- 静的サイトは `slidev build` で生成（GitHub Pages / 任意の静的ホスティングで配信可）

## Commands

```bash
cd {{PROJECT_PATH}}

npm install                                            # first time only

# 新規スライド雛形を作成
npm run new -- <topic> <profile> <internal|external> [brand]

# 例
npm run new -- product-intro product-company-overview external
npm run new -- weekly progress-report internal
npm run new -- research-update academic-research external default

# backward compatible: profile 省略時は product-company-overview
npm run new -- <topic> external

# プレビュー (ブラウザで自動起動)
npm run dev -- slides/<YYYY-MM-DD-topic>/slides.md

# 静的 HTML サイトとして build
npm run build -- slides/<YYYY-MM-DD-topic>/slides.md
# → dist/

# PDF として export（標準は per-slide）
npm run export -- slides/<YYYY-MM-DD-topic>/slides.md --output slides/<YYYY-MM-DD-topic>/<topic>.pdf

# Slidev の一括 /print 経路を調査したい場合のみ
npm run export:onepiece -- slides/<YYYY-MM-DD-topic>/slides.md --output slides/<YYYY-MM-DD-topic>/<topic>-onepiece.pdf
```

## Manuscript convention

- 配置: `slides/YYYY-MM-DD-<topic>/slides.md`
- 同フォルダに `style.css`（テーマインポート、`new-slide.sh` が自動生成）
- 一時ファイル: `*.local.md` または `<name>-local/`（gitignored）

## Directory layout

```
slides/<YYYY-MM-DD-topic>/
  slides.md       — 原稿（Slidev Markdown）
  style.css       — brand/theme 読み込み（@import で brands/<name>/ と themes/<name>/ を参照）
references/
  profile-selector.md
  visual-direction.md
  profiles/       — 資料タイプごとの作法
  patterns/       — 1枚ごとのスライド型
brands/
  default/
    brand.md      — brand 情報
    theme.css     — CSS variables
    assets/       — logo 等の置き場
themes/
  internal/
    style.css     — 編集前提・カジュアル・密度高め
  external/
    style.css     — 読まれる前提・ブランド準拠・余白広め
scripts/
  new-slide.sh    — 雛形作成スクリプト
slides-export.pdf — `--output` 未指定時の PDF エクスポート結果（gitignored）
```

## Profiles

資料の目的に応じて profile を選ぶ。詳細は `references/profile-selector.md` と `references/profiles/<profile>.md` を読む。

| Profile | 用途 |
|---|---|
| `consulting-proposal` | 経営向け提案、意思決定資料 |
| `service-proposal` | 顧客向け導入提案、営業資料 |
| `product-company-overview` | 会社紹介、プロダクト説明、事業紹介 |
| `startup-pitch` | ピッチ、事業コンテスト、投資家向け |
| `academic-research` | 大学研究発表、ゼミ、技術発表 |
| `progress-report` | 週次、月次、進捗報告 |
| `internal-meeting` | 社内MTG、論点整理、意思決定メモ |

枚数は固定しない。情報量、発表時間、配布用か投影用かに応じて、LLM が統合、分割、appendix 化を判断する。

## Patterns

Slidev Markdown では per-slide `class` で pattern を指定する。

```yaml
---
class: summary
---
```

代表 class:

- `cover`, `section`, `summary`, `problem`, `insight`, `solution`
- `comparison`, `roadmap`, `metrics`, `architecture`
- `research`, `method`, `findings`
- `status`, `risks`, `decision`, `next-actions`, `appendix`

## Brands

brand 指定がある場合は `brands/<brand>/brand.md` と `brands/<brand>/theme.css` を使う。未指定時は `default`。

deck local の `style.css` は以下を import する。

```css
@import url('../../brands/default/theme.css');
@import url('../../themes/external/style.css');
```

## Themes

| | internal | external |
|---|---|---|
| 用途 | 社内MTG、進捗報告、論点整理 | 提案書、説明資料、研究発表、公開資料 |
| 密度 | 高め | 控えめ |
| 余白 | 控えめ | 広め |
| 強み | 状況、論点、ToDo を素早く読める | 主張、根拠、比較、ロードマップを綺麗に見せる |
| brand | `brands/<name>/theme.css` の変数を参照 | 同左 |

テーマと brand の切り替え: `slides/<deck>/style.css` の `@import` パスを書き換える。

## Slidev frontmatter (deck 共通)

```yaml
---
theme: default          # Slidev built-in theme を base に CSS でカスタム
title: "<topic>"
info: |
  Generated by slide-web (profile: <profile>, theme: internal|external, brand: <brand>)
highlighter: shiki
lineNumbers: false
transition: slide-left
mdc: true
---
```

per-slide frontmatter (例):
```yaml
---
class: cover
---
```
```yaml
---
class: comparison
---
```

Slidev builtin layout も使えるが、まずは theme 側で定義した class pattern を優先する。

## Hard limits (slide-web specific)

| 項目 | 上限 | 超過時の対応 |
|------|------|--------------|
| 1スライドの本文行数 | 5行 | 要約 or 分割 |
| bullets | 6項目 | 分割 or `<v-clicks>` で順次表示 |
| 表行数 | 6行 | 分割 or 付録に逃がす |
| アニメーション要素 | 1スライド3個まで | 多用は AI 臭の元 |

## Adding a new theme or brand

1. `themes/<name>/style.css` を作成（既存テーマを参考に CSS 変数を定義）
2. `scripts/new-slide.sh` の theme バリデーションに `<name>` を追加
3. `BUILD.md` のテーマ表に追記
4. 動作確認: `npm run new -- test-<name> product-company-overview <name> && npm run dev -- slides/<...>/slides.md`

brand 追加:

1. `brands/<name>/brand.md` を作成
2. `brands/<name>/theme.css` に CSS variables を定義
3. logo は `brands/<name>/assets/` に置く
4. 動作確認: `npm run new -- test-brand product-company-overview external <name>`

## Iteration workflow

ユーザーから修正依頼が来たとき:

1. **slides.md を直接編集**する（生成済み HTML/PDF は触らない）
2. profile や pattern から外れた変更になっていないか確認する
3. プレビュー中なら hot-reload で即反映、停止中なら `npm run dev` で再起動
4. 確定したら `npm run build` (公開用) または `npm run export` (PDF 配布用)
5. 出力パスをユーザーに伝える

## Known limitations / 注意点

- Slidev の `slidev export` は **Playwright** に依存（初回 `playwright install chromium` 必要）
- この環境では一括 `/print` 経路で白紙 PDF が出ることがあるため、標準 export は `--per-slide` を使う
- この環境では `networkidle` 待ちが timeout しやすいため、npm script は `--wait-until load --timeout 120000` を指定する
- TOC や cross-slide link を PDF で使う場合だけ、`npm run export:onepiece` を検証用に使う
- 日本語フォントは OS 環境依存。PDF export 時は環境にインストール済みのフォントを使う
- `<v-click>` などのアニメーションは PDF export 時は静的化される（全要素同時表示）
- `mdc: true` の MDC 記法（`{ .class }` 等）は対応エディタが少ない — VSCode + Slidev 拡張推奨
