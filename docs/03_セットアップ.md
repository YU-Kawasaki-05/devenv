# 03. セットアップ

新メンバーが PC で開発を始められるようにするまでの手順です。**上から順番に**実行してください。

> 用語が分からなくなったら [`02_用語集.md`](02_用語集.md) を都度参照。

---

## 0. 前提

- OS: Windows / Mac / Linux のいずれか
- Windows の人は **WSL2 (Ubuntu)** を使うのを推奨 (このチームの開発はみな WSL2 上で動かしている)

---

## 1. 必要ツールのインストール

### 1.1 VSCode

公式サイトからダウンロードしてインストール: https://code.visualstudio.com/

### 1.2 git

ターミナルを開いて以下を実行:
```bash
git --version
```

`git version 2.x.x` のように出れば既にインストール済み。出なければ以下:
- Mac: `brew install git`
- Ubuntu/WSL2: `sudo apt update && sudo apt install git`
- Windows (WSL2 を使っているなら不要、生 Windows なら): https://git-scm.com/

### 1.3 Node.js (slide-gen など、Node を使う Skill 用)

```bash
node --version
```
`v20.x.x` 以上が望ましい。なければ [nvm](https://github.com/nvm-sh/nvm) 経由で:
```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
# ターミナル再起動後
nvm install 20
nvm use 20
```

### 1.4 Claude Code

```bash
npm install -g @anthropic-ai/claude-code
```

インストール後、認証:
```bash
claude
```
を実行すると、初回はブラウザで Anthropic アカウントへのログインが求められます。ログインするとターミナルに戻ってきます。

### 1.5 Codex (使う場合のみ)

```bash
npm install -g @openai/codex
```
認証:
```bash
codex
```
で初回ログインフロー。

### 1.6 GitHub Copilot (使う場合のみ)

VSCode の拡張機能マーケットプレイスで「GitHub Copilot」を検索してインストール → GitHub アカウントでサインイン。

---

## 2. リポジトリの取得 (clone)

devenv (正本リポジトリ) を含む、自分が触るプロジェクトを **`~/develop/` 配下** に取得します。

```bash
mkdir -p ~/develop
cd ~/develop

# 例: 担当プロジェクトが Ardors-website なら
git clone <Ardors-website のリモート URL> Ardors-website

# devenv も同じ場所に置く (まだ無ければ)
# devenv はリモート未公開の場合あり。チームリーダに確認
```

> **devenv がまだ git リモートに上がっていない場合**: チームリーダから直接渡してもらうか、`~/develop/devenv/` をローカルでコピーして使う。

---

## 3. VSCode で開く

```bash
code ~/develop/Ardors-website
```

または VSCode を起動 → `ファイル > フォルダを開く` で `~/develop/Ardors-website` を選択。

### 3.1 推奨拡張機能

VSCode の拡張機能タブ (`Ctrl + Shift + X`) で以下を入れておく:

- **Claude Code** (Anthropic 公式): VSCode 内で Claude Code が使える
- **GitHub Copilot** (使う場合)
- **EditorConfig for VS Code**: コーディングスタイルの統一
- **GitLens**: git の履歴が見やすくなる

---

## 4. プロジェクトに正本セットを配布する

**新規にプロジェクトを取得した直後**、または **正本が更新された後** にやる作業です。

### 4.1 まず差分確認

```bash
cd ~/develop/devenv
./scripts/diff.sh ~/develop/<プロジェクト名> --names-only
```

何も出なければ既に最新と一致しています。差分があれば次へ。

### 4.2 dry-run で何が変わるか確認

```bash
./scripts/sync.sh ~/develop/<プロジェクト名> --dry-run
```

「これらのファイルが変わるよ」と一覧が出ます。問題なさそうなら次へ。

### 4.3 実 sync

```bash
./scripts/sync.sh ~/develop/<プロジェクト名>
```

これで配布完了。プロジェクトに `.codex/`, `.agents/skills/`, `CLAUDE.md`, `AGENTS.md` が配置されます。

---

## 5. 動作確認

### 5.1 Claude Code で Skill が呼べるか

VSCode のターミナルで:
```bash
cd ~/develop/<プロジェクト名>
claude
```
を起動。プロンプトに `/` と打つと、利用可能な Skill (`/pr-review`, `/debug-investigator`, `/slide-gen` など) のリストが出ます。

### 5.2 Codex が hook を読み込んでいるか (Codex を使う場合)

Codex を起動した時の出力に「Loading workspace conventions」と出れば成功。

---

## 6. よくあるつまずきポイント

### Q: `claude` を実行したら「command not found」と言われる

A: `npm install -g` で入れた CLI が `PATH` に通っていない。`~/.bashrc` か `~/.zshrc` の末尾に以下を追加:

```bash
export PATH="$HOME/.npm-global/bin:$PATH"
```
追加後、ターミナル再起動 or `source ~/.bashrc`。

### Q: WSL2 で VSCode が使えない

A: VSCode の拡張機能「Remote - WSL」をインストール → VSCode 左下の青い `><` アイコンから「WSL ウィンドウで再オープン」を選ぶ。

### Q: Claude Code を起動したら何度もパーミッションを聞かれる

A: 普段安全に使うコマンド (例: `ls`, `cat`, `git status` など) はあらかじめ許可リストに登録できる。**Claude Code 内で `/permissions` コマンド** を打つと設定画面に入れる。

### Q: 正本が更新されていることに気づきたい

A: 定期的に:
```bash
cd ~/develop/devenv
git pull origin main         # 最新の正本を取得
./scripts/diff.sh ~/develop/<自分のプロジェクト> --names-only
```
を実行する。差分があれば 4.2 → 4.3 で反映。
