# 01. はじめに

## このマニュアルは何か

私たちのチームは、開発作業を **AI エージェント** (Claude Code / Codex / GitHub Copilot) と一緒に進めています。これらのエージェントには「**指示書 (Skill)**」「**安全装置 (Hook)**」「**プロジェクト方針 (CLAUDE.md / AGENTS.md)**」を渡して動かすと、毎回ゼロから説明しなくても期待する仕事をしてくれます。

ただし、複数のプロジェクトに同じ指示書をバラバラに置くと、**段々と内容がズレていって、どれが正しいか分からなくなります**。これを防ぐため、私たちは指示書の **「正本 (せいほん)」を 1 ヶ所に集約して、各プロジェクトに配布する仕組み** (= devenv) を持っています。

このマニュアルはその仕組みの使い方を説明するためのものです。

## 全体像 (ざっくり図)

```
┌────────────────────────────────────────────────────┐
│  ~/develop/devenv/   ← 正本リポジトリ (集約場所)     │
│   ├── templates/docs-first-web/   ← みんなで共有する基本セット │
│   ├── overrides/<プロジェクト名>/  ← 個別プロジェクト固有の上書き │
│   └── scripts/sync.sh             ← 配布スクリプト │
└──────────────────┬─────────────────────────────────┘
                   │ sync (配布)
       ┌───────────┼───────────┐
       ▼           ▼           ▼
  Ardors-website  schedule_app  lifeapp ...
  (.claude/, .codex/, .agents/skills/, CLAUDE.md, AGENTS.md がここに配布される)
```

要点:
- **正本は 1 ヶ所** (`~/develop/devenv/templates/`)
- **配布は一方向** (正本 → 各プロジェクト)
- **個別の差異は overrides で吸収** (lifeapp や marubo_ai は固有部分だけ上書きされる)

## なぜこの仕組みが必要なのか

### 問題1: バラバラに置くと、ある時から「どれが正しい?」となる

例: PR レビュー用の Skill を 5 プロジェクトにコピーで置くと、半年後にはそれぞれが少しずつ違って、「最新版はどれ?」と毎回悩む。

### 問題2: 1 ヶ所だけ更新して他を忘れる

PR レビューのチェック項目を強化したのに、コピー先に反映し忘れて、Ardors-website では新基準なのに schedule_app では旧基準のレビュー、ということが起きる。

### 解決: 正本 (1 ヶ所) + 配布 (sync) + 履歴 (git)

- 編集するのは **正本だけ**
- 配布は **sync スクリプトに任せる**
- いつ何を変えたかは **git の履歴**に残る

これで「最新がどれか」「いつ変わったか」「何故変わったか」が一目で分かるようになります。

## 誰向けに書かれているか

- **エンジニアリング初心者 (チームメンバー)**: これから AI エージェント開発を始める人
- **VSCode 初心者**: VSCode を使ったことがない or ほとんど使ったことがない人
- **既存メンバー**: 復習や、運用ルールの確認用

専門用語が出てきたら [`02_用語集.md`](02_用語集.md) を参照してください。

## 読み終わると何ができるようになるか

このマニュアルを最後まで読むと、以下ができるようになります:

1. **AI エージェントを呼び出して、コードレビューやスライド作成などを依頼**できる
2. **既存プロジェクトに正本セットを配布**できる
3. **新しいプロジェクトを管理対象に追加**できる
4. **正本を修正して、全プロジェクトに反映**できる
5. **エラーが出たときに自分で原因を切り分け**できる
