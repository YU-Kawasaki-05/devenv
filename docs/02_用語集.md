# 02. 用語集

このマニュアルで頻出する言葉をまとめました。**最初に通読する必要はなく、知らない言葉が出てきたときに引く辞書**として使ってください。

---

## カテゴリ A: AI エージェント関係

### Claude Code (クロード コード)
Anthropic 社の AI **Claude** を使う公式 CLI / VSCode 拡張機能。ターミナルや VSCode の中で対話しながらコードを書いたり調査したりできる。

### Codex (コーデックス)
OpenAI の AI コーディング支援ツール。Claude Code に似た立ち位置だが、内部の AI モデル (GPT 系) と挙動 (hook の仕組みなど) が違う。

### GitHub Copilot (ギットハブ コパイロット)
GitHub / Microsoft の AI コーディング支援。VSCode に組み込まれ、コードの自動補完や Agent モードでの作業を行う。

### エージェント / AI エージェント
人間の指示を受けて、複数ステップの作業 (調査 → 編集 → テスト) を自動で進める AI のこと。Claude Code / Codex / Copilot Agent はすべてこれ。

### ハーネス (Harness)
エージェントを「囲む」周辺の仕掛けの総称。Skill や Hook、CLAUDE.md などをまとめて「ハーネス一式」と呼ぶ。馬具の harness が由来 (馬 = AI を制御する仕掛け)。

---

## カテゴリ B: 指示書・設定ファイル系

### CLAUDE.md
プロジェクトのルートに置く、**Claude Code 向けの指示書**。「このプロジェクトでは git push しないで」「TypeScript strict で書いて」などプロジェクト固有のルールを書く。

### AGENTS.md
**Codex などその他のエージェント向けの指示書**。役割は CLAUDE.md と似ているが、対象のエージェントが違う。

### Skill (スキル)
AI が実行できる **小さな専門サービス**。例えば `pr-review` は PR レビューを得意とする Skill、`slide-gen` はスライド作成、`debug-investigator` は障害調査。AI に「`/pr-review` してくれ」と頼むとその Skill が呼び出される。

実体は `SKILL.md` という Markdown ファイル + 補助ファイル群。

### Hook (フック)
特定タイミング (コマンド実行前、セッション開始時 など) に **自動実行される検査スクリプト**。たとえば「危険な `rm -rf /` コマンドが出たら止める」などの安全装置。Codex で使われるのは Python スクリプト (`.codex/hooks/*.py`)。

## カテゴリ C: 配布の仕組み (devenv)

### devenv (開発環境)
`~/develop/devenv/` にある **正本リポジトリ**。Skill / Hook / 指示書を集約して各プロジェクトに配布する。

### Profile (プロファイル)
プロジェクトのタイプ別の **「セット」**。たとえば `docs-first-web` は「ドキュメント駆動の Web プロジェクト」用のセットで、9 つの Skill + 3 つの Codex agent + 5 つの Hook をまとめている。

### Template (テンプレート / 正本)
各 profile の中身。`devenv/templates/<profile>/` に置かれる。**この中身を編集すれば配布先全てに反映される**。

### Override (オーバーライド)
プロジェクト固有の上書き。テンプレートに対して「このファイルだけはこのプロジェクト専用」という差分を `devenv/overrides/<プロジェクト名>/` に置く。

例: `lifeapp` では Git の運用ルールが他プロジェクトと違うので、CLAUDE.md だけ override で固有版を保持している。

### Manifest (マニフェスト)
`devenv/manifest.yml` のこと。**「どのプロジェクトがどの profile を使うか」の対応表**。

### Sync (シンク / 同期)
正本 → プロジェクトへの **配布動作**。`scripts/sync.sh ~/develop/<project>` で実行。

### dry-run (ドライラン)
**「実際には書き換えずに、何が変わるかだけ見せる」モード**。`--dry-run` フラグを付けて実行する。本番反映前の最終確認に使う。

### Manifest の状態タグ

| 状態 | 意味 |
|---|---|
| **managed (管理対象)** | manifest に登録され、profile が割り当てられている |
| **pending (保留)** | 将来管理予定だが、今は条件が整っていない (manifest にコメントで明記) |
| **out of scope (対象外)** | 永続的に管理対象外と決めた (manifest にコメントで明記) |

## カテゴリ D: VSCode / コマンドライン基本

### ターミナル
キーボードでコマンドを打って実行する画面。VSCode では `表示 (View)` → `ターミナル` または `Ctrl + @ ` (Mac は `Ctrl + Shift + @`) で開く。

### コマンド
ターミナルに打つ命令文。例: `ls -la` (現在地のファイル一覧を詳細表示)。

### CLI (Command Line Interface)
コマンドで操作するインターフェース。「クリックする画面」(GUI) の対義語。Claude Code / Codex はどちらも CLI ツール。

### git
ソースコードのバージョン管理ツール。「いつ・誰が・何を変えたか」を記録する。

### git commit
変更内容を「ひとまとまり」として記録すること。雑に言うとセーブポイントを打つ動作。

### git push
ローカル PC の commit を、リモートサーバ (GitHub) に送る動作。チームに共有する瞬間。

### symlink (シンボリックリンク)
**ファイルへの矢印**。実体は別の場所にあって、symlink はそこを指すだけのポインタ。

例: `~/.agents/skills/pr-review` は `~/.claude/skills/pr-review` を指す symlink。中身を読みに行くと自動で実体に到達する。

### rsync
ファイルをコピー・同期するための高機能なツール。devenv の sync.sh が内部で使っている。「変更があるファイルだけ転送」「タイムスタンプを保つ」などの機能がある。

## カテゴリ E: エンジニアリング原則 (運用ルールの背景)

### DRY (Don't Repeat Yourself)
「同じ情報を複数箇所に書かない」原則。devenv で正本を 1 ヶ所に集約しているのはこれ。

### Single Source of Truth (真実源)
「これが正しい」と決められた **唯一の場所**。devenv の `templates/` がそれ。

### 一方向 sync
データの流れを **「正本 → コピー」の片方向だけ**に限定する設計。逆 (コピー → 正本) は許さないので、何が正しいかが揺らがない。

### dry-run ファースト
**実行前に必ず dry-run で結果を確認**してから本番を流す原則。「やった結果あれ?」を防ぐ。
