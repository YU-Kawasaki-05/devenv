# 05. トラブルシューティング

エラーや想定外の挙動に遭遇したときの対処集です。**症状から探して**読んでください。

---

## カテゴリ A: sync / 配布関連

### A1. `profile not found: <パス>` と言われる

**症状**: `./scripts/sync.sh ~/develop/<プロジェクト>` 実行時に出る。

**原因**: manifest.yml にそのプロジェクトが登録されていない。

**対処**:
```bash
# 一時的に profile を直接指定
./scripts/sync.sh ~/develop/<プロジェクト> --profile docs-first-web --dry-run
```
継続的に管理するなら manifest.yml に追加 ([04. B2](04_日々の使い方.md#b2-新しいプロジェクトを管理対象に追加する) 参照)。

### A2. `target not found: <パス>` と言われる

**症状**: 上記と似たエラー。

**原因**: パスが間違っている。

**対処**: `ls ~/develop/<プロジェクト>` でパスが存在するか確認。タイプミスや末尾のスラッシュに注意。

### A3. dry-run で大量の `>f..t......` が出る

**症状**: 実行ログに `>f..t......` がたくさん出る。

**原因**: ファイル**内容は同じ**で、最終更新時刻 (mtime) だけが違う状態。**正常**です。

**対処**: 気にせず実 sync を実行して OK。`scripts/diff.sh --names-only` でも何も出なければ問題なし。

### A4. dry-run で `>f.st......` が出ている、これは何?

**症状**: 内容差分があるファイルのサイン。

**意味**: そのファイルは sync によって **内容が書き換わる**。書き換わっていいのか確認:
```bash
./scripts/diff.sh ~/develop/<プロジェクト>   # 全文 diff
```

意図しない書き換えなら、override で固有版を保持する ([04. B3](04_日々の使い方.md#b3-プロジェクト固有の上書き-override-を追加する)) か、正本を直す。

### A5. 一度 sync したけど元に戻したい

**症状**: 反映後、想定外の動作になった。

**対処**:
- そのプロジェクトが git 管理下なら: `cd ~/develop/<プロジェクト> && git status` で変更ファイルを確認 → `git restore <ファイル>` で戻す
- git 外なら: 戻す手段が限られる。だから **dry-run の確認は省略しない**こと

### A6. override が効いていない (テンプレ版が上書きされてしまう)

**症状**: 固有版を `overrides/<project>/` に置いたのにテンプレ版で上書きされる。

**確認ポイント**:
1. ディレクトリ名がプロジェクトのディレクトリ名 (basename) と一致しているか
   ```bash
   ls ~/develop/devenv/overrides/        # ここの名前
   basename ~/develop/<プロジェクト>      # ここの名前
   ```
   両者が一致していなければ override は効きません。
2. パス構造がテンプレと同じか
   - 正: `overrides/lifeapp/CLAUDE.md` (テンプレの CLAUDE.md と同じ位置)
   - 誤: `overrides/lifeapp/lifeapp/CLAUDE.md` など

## カテゴリ B: Claude Code / Codex 関連

### B1. `claude` コマンドが見つからない

**対処**: [03. セットアップ Q1](03_セットアップ.md#q-claude-を実行したらcommand-not-foundと言われる) 参照。

### B2. Skill のスラッシュコマンドが出てこない

**症状**: `/pr-review` が補完されない。

**原因**:
- そのプロジェクトに `.agents/skills/pr-review/` が無い (sync 未実行)
- グローバル Skill (`~/.claude/skills/pr-review/`) も無い

**対処**:
```bash
ls ~/.claude/skills/
ls ~/develop/<プロジェクト>/.agents/skills/
```
必要なら sync を実行 ([04. B1](04_日々の使い方.md#b1-担当プロジェクトの正本セットを最新化する))。

### B3. Codex が hook を読み込まない

**症状**: Codex 起動時に `Loading workspace conventions` が出ない。

**確認**:
```bash
cat ~/develop/<プロジェクト>/.codex/hooks.json
ls  ~/develop/<プロジェクト>/.codex/hooks/
```
両方ない場合は sync 未実行。実行してください。

### B4. パーミッションを毎回聞かれる

**対処**: Claude Code 内で `/permissions` でよく使うコマンドを許可リストに追加。プロジェクト単位の設定は `.claude/settings.local.json` に保存される (個人ファイルなので git 管理外)。

## カテゴリ C: VSCode / 環境関連

### C1. WSL2 でファイルが見つからない

**症状**: VSCode で操作しているがターミナルからファイルが見えない、その逆。

**原因**: VSCode が Windows 側で動いていて、WSL のホームディレクトリと食い違っている。

**対処**: VSCode を WSL モードで開く。左下の青い `><` アイコンから「WSL: Ubuntu に再接続」。

### C2. ターミナルでコマンドが日本語で文字化けする

**対処**:
```bash
echo $LANG   # ja_JP.UTF-8 になっているか
```
なってなければ `~/.bashrc` に追加:
```bash
export LANG=ja_JP.UTF-8
```

### C3. `git pull` で merge conflict が出た

**症状**: `~/develop/devenv` を `git pull` したら conflict。

**対処**:
- 手元で正本を変更していて、リモートにも別の変更が入ったときに発生
- 落ち着いて conflict したファイルを開く → `<<<<<<<`, `=======`, `>>>>>>>` のマーカ部分を手動で解消
- 不安なら一旦 `git stash` で自分の変更を退避してから `git pull` し、その後 `git stash pop` で戻す
- 分からない場合はチームメンバーに相談

## カテゴリ D: 困ったときの汎用フロー

### D1. 何か変だが原因が分からない

1. **再現性を確認**: もう一度同じ操作で再現するか
2. **エラーメッセージを正確に読む**: 「だいたい」ではなく完全コピー
3. **直前の操作**を思い出す: 「いつから変?」「最後に何を変えた?」
4. **`git status` / `git log -3` で履歴確認**: 想定外の変更がないか
5. **AI エージェントに聞く**: `/debug-investigator` を呼んで状況を投げる

### D2. AI エージェント (Claude Code) を頼る

エラー文・スタックトレース・状況を貼って:
```
このエラーが出ました: [貼り付け]
直前にやった操作: [説明]
原因と対処を教えてください
```

たいていは Claude Code が一緒に切り分けてくれます。

### D3. それでもダメなら

- チームのメンバーに **「やったこと + 出たエラー」** をセットで聞く
- 「動かない」だけでなく「**何をしたら何が起きた**」が再現に必要
- 解決したら、対処を **このマニュアルに追記** して次の人を救う

このマニュアルは「育てるドキュメント」です。新しい問題と対処を見つけたら、このファイルに追記してください。

```markdown
### X番号. 症状の短い説明

**対処**:
具体的な手順をコードブロックで
```
