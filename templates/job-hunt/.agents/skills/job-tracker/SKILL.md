# 応募管理

## Role

`tracker.md` を、候補企業リストだけでなく「応募単位」と「選考ステップ履歴」を追える形で管理する。

## Core Model

1つの応募は、企業ではなく **企業 + 部門 + 職種 + 応募種別** で識別する。
例: `PwC / コンサルティング / Business Consultant / サマーインターン` と `PwC / コンサルティング / ITSC / 本選考` は別応募として扱う。

## Standard Stages

- 情報収集
- 応募準備
- ES作成中
- ES提出済み
- Webテスト/適性検査
- 書類選考中
- GD/グループワーク
- ケース/筆記
- 一次面接
- 二次面接
- 最終面接
- インターン参加
- 早期選考案内
- 内定
- 不合格
- 辞退

ステータスは `未応募` / `進行中` / `通過` / `不合格` / `内定` / `辞退` / `保留` を使う。

## Update Rules

- 結果・日程・締切が分かったら、必ず `## 選考イベント履歴` に1行追加する。
- ユーザーが日付・締切・開催日程・希望ターム・面接日・Webテスト期限・提出期限・結果通知予定を共有した場合は、必ず `tracker.md` に反映する。該当企業の `questions.md` / `research.md` と、必要に応じて `notes/作業アーカイブ/` にも保存する。
- 日付は相対表現だけで残さず、`YYYY-MM-DD`、必要なら `HH:MM` とタイムゾーンを付ける。ユーザーが相対日付で共有した場合は、現在日付を基準に絶対日付へ変換して記録する。
- 未確定の日程や候補タームも、確定情報と分けて「候補」「ユーザー共有情報」として記録する。
- 日程情報を受け取ったら、既存の `tracker.md`、該当企業/他社の `questions.md` / `research.md`、作業ログを確認し、日程衝突、近接締切、予約変更可否、代替ターム、辞退・調整可能性を評価する。
- 複数タームから選ぶ場合は、他社日程との衝突の少なさ、志望度、早期選考接続、変更可否を踏まえて推奨順位を出す。結論だけでなく、主な衝突・残る代替案もメモに残す。
- 進行中の応募は `## 選考パイプライン` に置く。
- 不合格・内定・辞退は `## 完了` に移す。ただし履歴は残す。
- 未応募企業は優先度別候補リストに置く。
- 日付は `YYYY-MM-DD`。時期だけなら `2026-06上旬` のように書く。
- 不明な情報は空欄にせず `要確認` と書く。
- 既存履歴は削除しない。訂正時は備考に `訂正:` を残す。

## Process

1. `tracker.md` を読む。
2. 操作を分類する: 新規応募、ステージ更新、結果記録、締切追加、候補追加、確認のみ。
3. 応募IDがなければ作る。形式は `<企業略称>-<職種略称>-<YYYY種別>` を目安にする。
4. 日程・締切が含まれる場合は、既存の他社日程と衝突確認を行い、必要なら企業別メモに日程比較を残す。
5. `選考パイプライン` / `完了` / `選考イベント履歴` を一貫して更新する。
6. Notion MCP が有効な場合は同じ粒度で同期する。無効なら `tracker.md` のみ更新する。
