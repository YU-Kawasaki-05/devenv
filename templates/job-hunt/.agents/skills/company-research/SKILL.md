# 企業リサーチ

## Role

就活用に企業・部門・職種・インターン/選考情報をWeb検索で調査し、`companies/<path>/` に保存する。

重要:
- 必ずWeb検索する。古い記憶だけで書かない。
- 複数部門・複数職種がある企業は、各候補部門を調査対象にする。推奨1部門だけで終わらせない。
- 情報は `公式確認済み` / `外部媒体のみ` / `未確認` に分ける。
- 日付は絶対日付で書く。相対表現だけで残さない。

## Directory Rules

| ケース | 保存先 | 例 |
|---|---|---|
| 単体企業で部門不要 | `companies/<会社名>/` | `companies/LayerX/` |
| グループ企業・複数部門・複数職種 | `companies/<グループ名>/<部門名>/` | `companies/PwC/コンサルティング/` |
| グループ/企業共通 | `companies/<グループ名>/_overview.md` | `companies/EY/_overview.md` |

複数部門が見つかった場合:
1. `companies/<グループ名>/_overview.md` を必ず作る。
2. 応募候補として現実的な部門・職種ごとに `research.md` と `questions.md` を作る。
3. 部門が多すぎる場合でも上位3〜5部門を個別化し、残りは `_overview.md` の「追加調査候補」に残す。
4. 既存ファイルは削除しない。更新時は調査日つきで追記・整理する。

## Research Depth

標準調査で見るもの:
- 公式: 会社概要、事業/サービス、採用、インターン、募集要項、ニュース/IR
- 採用媒体: MyPage、外資就活、ワンキャリア、マイナビ、リクナビ、LabBaseなど
- 補助: OpenWork等の口コミは補助扱い。断定根拠にしない
- 比較: 同じ志望職種で比較される競合

深掘り観点:
- 事業モデル、収益源、主要顧客、成長領域
- 部門/職種別の仕事内容、求めるスキル、配属可能性
- 2028卒/サマーインターン/早期選考の公開状況、締切、選考フロー、ES設問
- 待遇、勤務地、働き方、福利厚生、転勤、残業リスク
- 最近2年程度のニュース、AI/DX/生成AI/データ活用トピック
- 自己分析との接続: ロート製薬AI推進室、塾Chatbot、テスト自動化、業務改善、人懐っこさ
- 志望動機に使える材料、面接で深掘りされそうなリスク

## Workflow

### Mode A: 部門指定あり

1. 指定部門を調査する。
2. 同じ企業内に近い部門・併願候補があるか確認する。
3. 指定部門の `research.md` / `questions.md` を作る。
4. 近い候補部門が2つ以上ある場合は `_overview.md` に比較表を作り、必要に応じて各部門ディレクトリも作る。

### Mode B: 部門未指定

1. `self/` を読む: `profile.md`, `strengths.md`, `pr_templates.md`, `experiences/` 全ファイル。
2. 企業の事業構造・採用コース・部門・職種を調査する。
3. 各部門を ★★★ / ★★ / ★ で評価する。
4. ★★★ と ★★ 上位の部門は原則として個別ディレクトリを作る。
5. `_overview.md` に全体比較・おすすめ・注意点・追加調査候補を残す。

評価軸:

| 評価軸 | 内容 |
|---|---|
| 経験マッチ | AI活用支援、Chatbot開発、要件定義、QA自動化、業務改善との重なり |
| 強みマッチ | 学びながら動く力、課題理解、対人関係構築が活きるか |
| 志望軸マッチ | 報酬、成長、WLB、人間関係、技術とビジネスの接点 |
| 市場価値 | 転職市場で評価される経験が積めるか |
| 選考現実性 | 28卒採用/インターンの公開状況、選考難易度、準備負荷 |
